# Demo narration

Live Claude Opus 5.5 · edited playback; synthesized narration with the macOS Samantha voice.

## 1. A conversation with your files

This is the LLM Powered File System Assistant, built for the Airtribe assignment. Ask a question in plain English, inspect the file tool calls, and get an answer based on document content. The examples in this video were generated by live Claude Opus five point five. Waiting time is shortened, and the file operations are real.

## 2. Four tools. Three document formats.

Part A is implemented in fs tools dot py. Read file extracts text and metadata. List files discovers the available documents. Search in file returns case insensitive matches with context. Write file creates a text output and any missing folders. The sample set contains eight fictional resumes across PDF, Word, and plain text.

## 3. Claude chooses the next action

Part B describes these functions with strict JSON schemas. The program sends the question and tools to Anthropic. It executes complete tool calls locally and returns all their results together. The entire assistant response, including signed thinking blocks, is preserved for the next request. The loop stops when Claude provides the final answer.

## 4. 01 · Read every resume

The first required query asks the assistant to read all resumes. The log shows a directory listing, followed by one read for each of the eight files. PDF page counts appear in the results, including Priya Sharma’s two page resume. The answer covers the complete set rather than guessing names or skipping a format.

## 5. 02 · Find Python experience

The second query searches for Python experience. All eight resumes are checked, including different capitalizations and phrases such as Django slash Python. Four candidates have professional experience: John Doe, Priya Sharma, Elena Rodriguez, and David Kim. Sofia Novak has a Monty Python hobby, so a text match alone is not enough to qualify her.

## 6. 03 · Create a summary file

The third query asks for a summary of John Doe’s PDF. The assistant reads the resume and calls write file with the generated Markdown. The program creates the summaries directory and reports the destination and byte count. The saved file is actual output from that tool call, rather than text displayed only in the chat.

## 7. The saved artifact

Here is the generated summary. It captures John’s backend engineering experience, key skills, work highlights, and education. The original resume stays intact. Existing files are replaced only when the assistant created them, and writes are atomic. A committed copy of the example is kept separately so new users can run the default summary query.

## 8. Failures become useful feedback

Missing files return structured errors rather than crashing the conversation. Tools refuse outside paths, hidden credentials, and executable outputs. The test suite also covers corrupt documents, encrypted files, symlink races, incomplete tool calls, conversation reset, and API failures. Two hundred and fifty seven tests pass, with ninety four percent overall line coverage.

## 9. Ready to explore

To run the project, install the pinned requirements and set your Anthropic API key. Multi workspace keys also need a workspace ID. Start the interactive chat, or pass a question directly. The repository includes the three example queries, captured transcripts, the generated summary, and the validation report. Every file action remains visible in the tool log.
